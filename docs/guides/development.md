# 开发与交付指南

本文维护日常工作流程，不重复启动步骤和技术参考。首次运行见 [快速开始](quick-start.md)。

## 1. 先确认当前授权阶段

遵守 [协作规则](../../AGENTS.md)：讨论 → 独立方案 → 方案审查 → 实施 → 独立验收。
讨论和方案不授权业务实现；验收默认只读。每次围绕一个功能点推进，不顺手扩展其他领域。

## 2. 修改前盘点

```bash
git status --short
git diff --stat
```

保留用户已有变更；相邻 `../calles` 只读。跨服务、认证、消息和数据库事项先阅读
[架构设计](../architecture.md)、[迁移计划](../migration-plan.md) 及相应契约。
确认调用方、数据所有者、权限、同步依赖和回退限制；冲突无法安全合并时停止修改。

## 3. 实施与同步维护

| 变更 | 必须同步的资料 |
| --- | --- |
| HTTP、JWT 或事件 | [契约](../contracts/README.md)、兼容用例、已知调用方 |
| 数据库 | 服务私有迁移脚本、空库 Schema 快照、数据库参考和回填/回退说明 |
| 配置与环境变量 | 本地配置、`.env.example`、相关部署或 Nacos 指南，不提交真实值 |
| 服务职责、数据所有权、跨服务调用 | 架构文档、领域设计与新 ADR |
| 网关路由 | 路由配置、契约路径与架构路由表 |

只做完成当前目标需要的变更。沿用现有依赖版本、命名和代码风格，不夹带全仓库格式化或升级。
具体代码要求见 [编码规范](coding-standards.md)。

数据库结构以可审查 SQL 演进，不假定 Flyway/Liquibase 已接入。同步调用先论证异步方式不能满足
需求，再声明超时、失败语义、重试上限；本地事务不得覆盖远程调用或消息发布。

## 4. 按风险验证

- 代码：至少编译受影响模块；接口和业务分支补充对应测试。
- 配置：YAML 可解析、受影响服务重新打包并启动探测。
- 认证和网关：验证正常链路、错误凭据、身份伪造、刷新和撤销以及依赖故障。
- 数据和消息：验证幂等、兼容、失败重试与一致性；不得用生产数据试跑。
- 文档：核对文件链接、命令路径、契约字段和现状标记；纯文档变更不冒充运行验收。

命令和用例集中在 [测试指南](testing.md)，不要通过跳过失败测试制造“通过”结果。

## 5. 交付与回退

交接记录目标和非目标、实际改动、契约/数据变化、执行命令及结果、未验证项、回退方式和遗留风险。
跨服务事项写入对应领域设计或 ADR，不新增独立工作记录目录。

代码回退不等于数据回退：保留已写入数据、消息和新建结构，按已审查的补偿或兼容策略处理。
任何切流、双写、密钥轮换、破坏性数据操作都必须另行取得明确确认。
