# 数据库初始化与结构验证

## 适用范围

仅用于已确认的隔离本地空库。当前五张表及所有权见 [数据库参考](reference/database-schema.md)。
本页不创建真实账号、不导入旧系统数据，也不授权修改生产、共享或未知数据库。

**当前 Compose 只挂载 MySQL 数据卷，没有挂载初始化 SQL。启动容器不会自动创建业务表。**
Compose 初始化数据库和用户所用变量以仓库配置为准；已有数据卷不能视作空库。

## 本地空库操作

1. 按 [快速开始](guides/quick-start.md) 配置本地连接信息并启动 MySQL。
2. 核对主机、端口、库名和用途，确认不是旧系统或共享环境。
3. 在宿主机安装 MySQL 客户端后运行以下命令，交互输入密码；变量需由本地环境安全注入。

```bash
# -p 只触发交互输入，不把密码放到命令行或文档。
mysql --host=127.0.0.1 --port=3306 --user="$MYSQL_USER" --password --database="$MYSQL_DATABASE"
```

在从仓库根目录启动的客户端中执行：

```sql
-- 先核对目标；输出不应包含账户业务数据。
SELECT DATABASE();
SHOW TABLES;
-- 仅在确认目标为空库后执行当前 Schema 快照。
SOURCE db/init/schema.sql;
-- 核验结构，不查询密码哈希或真实用户记录。
SHOW CREATE TABLE auth_account;
SHOW CREATE TABLE user_profile;
```

没有宿主机客户端时，可在容器内交互连接并手工输入经过核对的 SQL；本页不提供携带密码的
非交互管道或自动修改实例的替代脚本。

## 外部数据库与已有库

外部数据库的建库、账号和最小权限由该环境管理员配置；本地环境变量必须与其对应。
不能复用文档里的固定口令，也不能照抄全库通配授权作为生产设置。

已有库先比较 `SHOW CREATE TABLE` 与服务私有 `db/schema/` 定义。`IF NOT EXISTS` 不会升级列类型、主键或
补齐数据；例如已有非 UUID 主键的表，不能通过重跑初始化脚本完成身份迁移。
需单独提供前向兼容、回填、一致性校验、备份和回退方案并审查后执行。

## 验证与回退限制

核验五张表的字段、主键、唯一索引、状态/逻辑删除约束和字符集，确认认证连接和用户连接各自只访问自有表。
DDL 成功不代表注册与资料业务可用，后续执行 [认证测试矩阵](guides/testing.md)。
失败时保留错误和结构证据，不通过删库、删表或删除 Docker 数据卷重试。
空库初始化后的新表也不自动授权删除；已有业务数据时回退必须按已确认方案进行。
