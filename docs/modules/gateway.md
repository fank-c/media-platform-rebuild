# 网关模块 · gateway-service

网关是客户端访问业务 API 的统一入口，负责按路径转发请求，并在转发前建立已认证身份。它不创建账号、编辑资料或编排文件上传；这些工作由对应服务执行。当前默认端口为 8000，通过服务发现找到下游实例，运行环境的连通性本次未验证。

## Part 1：请求转发

### 根据业务路径找到服务

客户端使用网关地址访问以下路径，路由由 `application.yml` 配置定义，而不是由认证过滤器实现：

| 路径 | 目标服务 | 当前业务范围 |
| --- | --- | --- |
| `/api/auth/**` | auth-service | 注册、登录、刷新与身份相关接口。 |
| `/api/users/**` | user-service | 用户资料接口。 |
| `/api/files/**` | file-service | 文件业务接口，不代理签名对象正文传输。 |
| `/api/content/**` | content-service | 仅预留路由，下游无业务接口。 |
| `/api/audit/**` | audit-service | 仅预留路由，下游无业务接口。 |
| `/api/interactions/**` | interaction-service | 仅预留路由，下游无业务接口。 |
| `/api/recommend/**` | recommend-service | 仅预留路由，下游无业务接口。 |

路由使用 `lb://服务名`，依赖服务发现返回可用实例；有路由配置不等于目标业务已存在，也不等于实例已启动。当前配置没有为这些路径剥除 `/api` 前缀，下游 Controller 使用相同业务前缀。

### 哪些请求不需要已有访问令牌

默认白名单为 `/api/auth/ping`、`/api/auth/login`、`/api/auth/register`、`/api/auth/refresh`、`/actuator/health` 和 `/actuator/info`。白名单按路径匹配，不是“整个认证模块匿名开放”，也不是按 HTTP 方法细分。

这些请求跳过访问令牌验证，但仍清除客户端提交的身份头。登录仍检查密码，刷新仍检查刷新凭据；白名单并不替代具体功能的输入验证。用户公开资料没有加入此白名单，因此仍需登录。

源码入口：[网关路由与白名单](../../service/gateway-service/src/main/resources/application.yml)。

## Part 2：身份校验与传递

### 从访问令牌得到下游身份

非白名单请求必须带 `Authorization: Bearer <accessToken>`。当前代码要求这个前缀，拒绝空令牌或令牌内部含空白的格式。处理顺序为：

1. 先提取凭据；缺失或格式不符时返回 JSON `401`，不转发业务请求。
2. 按令牌摘要查询 Redis 中的验证缓存。未命中则向认证服务 `POST /api/auth/verify`，提交令牌等待验证结果。
3. 只有 `valid=true` 且主体、角色、类型、会话 ID 均非空，才按认证成功继续。
4. 删除客户端自带的 `X-User-Id`、`X-User-Role`、`X-User-Type`、`X-Session-Id`，重新写入认证结果，再按路由转发。

网关只传递身份，不替业务服务判断“文件是否属于本人”或“管理员能修改什么”。下游通过公共请求上下文读取身份，继续执行自己的权限检查。

### 缓存、依赖故障与退出

当前写缓存的代码没有按 `valid` 筛选，成功和无效验证结果都可能缓存。Redis key 使用令牌 SHA-256 摘要，不保存完整令牌作为 key。有过期时间的结果，其缓存期限取 `gateway.auth.cache-ttl` 与剩余时间的较小值；没有过期时间的结果使用配置期限，仓库默认 10 分钟。正常有效令牌的验证响应带过期时间，因此缓存不会超过它的剩余期限。

Redis 读失败按缓存未命中回源，写失败不阻断这次已通过的认证。认证服务调用有 3 秒等待上限，异常或超时转为无效结果，最终网关返回 `401`；因此这个状态不一定只意味着用户输错了凭据，也可能是认证依赖不可用。已有缓存命中则不会在当次请求回源检查撤销。认证服务故障转换出的无效结果也可能被缓存，所以即使依赖恢复，同一令牌仍可能在缓存到期前被拒绝；当前没有自动识别依赖恢复后提前清理这类缓存的机制。

请求经网关完成 `/api/auth/logout` 转发后，会尝试删除本次令牌的缓存。删除失败被记录但不强制改写下游结果；并发请求也可能已读到缓存或重新写回结果。因此不能承诺退出后所有请求立即被拦截，也不能承诺账号状态改变会主动清空全部缓存。

源码入口：[认证过滤器](../../service/gateway-service/src/main/java/com/calles/platform/gateway/filter/AuthGlobalFilter.java)、[认证回源调用](../../service/gateway-service/src/main/java/com/calles/platform/gateway/service/AuthServiceClient.java)、[验证缓存](../../service/gateway-service/src/main/java/com/calles/platform/gateway/service/AuthCacheService.java)。

### 身份头的边界

清理并重写身份头只约束经过网关的请求。业务服务的公共过滤器本身读取这些 Header，不自行验签；如果外部能绕过网关直连业务服务，就不能仅凭这些 Header 认定身份可信。阻止服务直连需要实际环境的网络访问控制，本次没有核验该条件，不将“经网关时已清洗”写成“所有入口均已防护”。

## 验证方式与当前结果

应验证白名单及非白名单、伪造身份头被清除、正确路由转发、Redis 故障回源、认证服务超时、缓存不超过令牌剩余期限，以及退出与并发请求交错。真实入口还应检查外部不能直连业务服务。
