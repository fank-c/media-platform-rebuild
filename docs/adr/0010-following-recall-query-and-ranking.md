# ADR 0010：关注召回采用查询式两阶段召回与本地排序

## 状态

已采纳（追认）

## 背景

首页推荐需要将用户当前关注作者的近期作品纳入 `FOLLOWING` 通道。关注关系属于 `user-service`，公开播放量属于 `interaction-service`，推荐服务不能跨服务访问表或维护关系副本。首页召回还受 500ms 全局等待预算约束，依赖失败必须可区分降级。

## 决策

1. 推荐服务每轮固定一个本地时间锚点，先通过用户服务内部接口查询最近最多 1000 个有效关注作者，再查询自身候选表中窗口内最新最多 100 条 ACTIVE 作品。
2. 推荐服务通过互动服务批量读取公开累计播放量，在本地执行时间半衰期与 `log1p` 播放量评分，并按分数、发布时间、视频短码稳定排序。
3. 用户服务与互动服务各使用独立具名 Feign 客户端，连接超时 50ms、读取超时 100ms、请求内零重试，并只透传当前 `traceId`。
4. 关注作者查询失败时通道返回空；统计查询失败时保留作品并按零播放量排序。推荐编排继续负责全局 500ms 超时、过滤、混排和补位。
5. 关注事件消费继续只记录事实，不参与本轮关系查询；不新增关注关系副本、播放量副本、双写或兼容路径。

## 备选方案

| 方案 | 不选的原因 |
| :--- | :--- |
| 推荐侧镜像关注关系并消费事件维护 | 引入第二个关系所有者，存在延迟与一致性问题，超出当前开发阶段范围 |
| 逐作者或逐视频远程调用 | 调用次数不可控，无法满足首页预算 |
| 在互动服务保存推荐专用播放量副本 | 重复计数所有权，增加同步链路与失效处理 |

## 后果

- 关注召回依赖用户和互动两个只读接口，故障可以局部降级，不阻断其他推荐通道。
- 作者集合和候选集合均有上限，较早关注作者或窗口内较旧作品可能不进入本轮候选；本次不提供作者公平配额。
- 公开播放量沿用互动服务汇总快照，允许存在汇总延迟；统计失败不会丢弃关注作品。
- 候选表新增 `(author_id, status, published_at, video_id)` 复合索引，并同步空库建表脚本。
