# ADR 0002: 对象存储预签名直传与下载作为网关的受控例外

## 状态

**Accepted（已采纳，追认）**。决策在 `file-service` V1 直传和下载地址上线时就已生效，本文补齐记录。

## 背景

平台规定客户端流量统一走网关（`/api/<domain>/...`）。但大文件（音视频原片）的上传下载如果也经过网关和 `file-service` 中转，会有三个问题：

- 网关和服务的带宽、内存被大流量占满，很难扩容。
- 请求时间长，容易超时，断线也没法续传。
- 对象存储本身已经具备分片、限速和高可用能力，服务再转一道没有额外价值。

`AGENTS.md` 已经写明：“MinIO 预签名 PUT/GET 仅作为经 ADR 确认的受控例外”。本文就是这份 ADR。

## 决策

1. **只有文件字节流绕过网关，业务 API 仍然走网关。** 初始化上传、确认、查询、申请下载地址、删除，都必须经网关调用 `file-service`，需要登录。
2. **客户端拿着 `file-service` 签发的短期预签名 URL（带签名和过期时间的临时地址）直接访问对象存储**：

   | 用途 | 签发接口 | 默认有效期 | 配置键 |
   | :--- | :--- | :--- | :--- |
   | 上传 PUT | `POST /api/files/direct-upload`（V1） | 15m | `file.put-ttl`（`FILE_PUT_TTL`） |
   | 上传确认截止 | 同上 | 30m | `file.upload-ttl`（`FILE_UPLOAD_TTL`） |
   | 下载 GET | `GET /api/files/{id}/download-url` | 2m | `file.get-ttl`（`FILE_GET_TTL`） |

3. **约束**：
   - Bucket 是私有的，禁止匿名读写，也禁止客户端或其他服务持有 AK/SK。
   - 签名只针对单个对象 Key。Key 由服务端生成，客户端不能自己指定路径。
   - 上传前先写 `PENDING` 元数据。确认时服务端要读取对象核对大小，通过后才标记为完成。超过确认截止时间的上传由清理任务回收。
   - 只给本人名下已完成、状态正常的文件签发下载地址，签发前先 HEAD 核对对象，响应带 `Cache-Control: no-store`。
   - 预签名 URL 是临时凭证，不能写进日志。
4. **适用范围**：阿里云 OSS（默认，`FILE_STORAGE_TYPE=ALIYUN_OSS`）和 MinIO 两种存储都适用。其他服务不能自己签发预签名 URL，只能通过 `file-service` 获取。
5. **V2 暂存直传**（带 checksum 签名、`staging/` 转 `permanent/`）的新入口已经停用，默认关闭（`file.direct-upload-v2.enabled=false`），原因是当前 OSS 适配器不支持 checksum PUT 签名。已有的 V2 记录继续按本 ADR 的约束处理。

## 不在本例外范围内

- 前台播放用的资源 `/api/files/assets/**` 走网关代理（HMAC 签名加网关 IP 限流），不是预签名直连。
- 服务之间读取文件用的内部下载地址（`GET /api/files/internal/{id}/download-url`）只能在集群内部调用，网关会拦截 `/internal/**`。它签发的仍是本 ADR 约束的短期 GET 签名。

## 备选方案

| 方案 | 不选的原因 |
| :--- | :--- |
| 所有字节流都经网关和 `file-service` 中转 | 带宽和内存成本高，大文件容易超时 |
| 公共读 Bucket 加 CDN | 私有文件会暴露，也做不了访问控制 |
| 给客户端下发 STS 临时密钥 | 权限范围比“单个对象 + 短时间”大，客户端实现也更复杂 |

## 后果

- **收益**：大文件流量不再经过网关，服务端可以横向扩展；上传下载稳定性交给对象存储。
- **代价与风险**：
  - URL 泄露后，在有效期内谁都能访问。所以有效期要尽量短，而且不能写日志。
  - 客户端跨域访问对象存储时，需要在 Bucket 上配置 CORS。
  - 客户端上传完“不确认”会留下孤儿对象，所以必须保留过期清理任务。
- **变更规则**：延长有效期、放宽 Key 范围、新增直连用途，或者允许其他服务签名，都需要写新的 ADR。
