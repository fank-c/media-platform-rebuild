# 架构决策记录 (ADR)

本目录记录 Calles Media Platform 的重要架构决策。每个决策都包含背景、方案、备选项、影响和验证方式。

## 什么时候写 ADR？

当面临以下情况时，应该创建 ADR：

- **技术选型**：选择框架、数据库、消息队列、存储方案
- **架构模式**：微服务拆分、事件驱动、CQRS、缓存策略
- **重大重构**：改变核心抽象、迁移数据模型、替换关键组件
- **跨团队影响**：影响多个服务或团队的技术决策
- **安全与合规**：认证授权方案、数据加密、审计日志

ADR 不是变更日志，也不是详细设计文档。它记录的是"为什么这样做"而不是"怎么做"。

## 如何编写 ADR？

1. 复制 [0000-template.md](./0000-template.md) 作为起点
2. 使用递增编号：下一个编号是 `0005`
3. 文件名格式：`NNNN-short-descriptive-title.md`
4. 标题使用中文，简洁描述决策内容
5. 包含以下必填部分：
   - **状态**：提议中 / 已接受 / 已废弃 / 已替代
   - **背景**：为什么需要做决策？当前痛点是什么？
   - **决策**：我们决定做什么？
   - **备选方案与取舍**：考虑过哪些方案？为什么没选它们？
   - **影响与风险**：这个决策会带来什么影响？有哪些风险？
   - **验证与回退**：如何验证决策正确？失败时如何回退？

## ADR 生命周期

- **提议中**：决策正在讨论，尚未最终确定
- **已接受**：决策已通过并开始执行
- **已废弃**：决策被证明不适用，不再遵循
- **已替代**：被新的 ADR 替代，在文档中注明替代者编号

废弃或替代的 ADR 不删除，保留作为历史记录。状态变更时更新文档头部的状态字段和日期。
