# 无破坏故障排查

先收集脱敏事实，再区分构建、基础设施、配置和业务问题；不要一上来删卷、清库、强杀进程或刷新密钥。
本地启动步骤见 [快速开始](../guides/quick-start.md)。

## 诊断顺序

```bash
# 只检查状态与配置，不修改部署或数据。
java -version
./mvnw -version
docker compose config -q
docker compose ps
```

Docker 命令失败先区分 CLI、Compose 语法和守护进程不可用；不能自动归因于工程配置。
需要日志时只查看相关服务，输出给他人前检查是否含敏感值。

## 按症状定位

| 症状 | 首先检查 | 后续动作与禁区 |
| --- | --- | --- |
| 公共模块找不到或 classpath 被拆分 | 当前路径含 `:`，公共模块是否安装 | 用 `./build.sh` 的顺序构建；不直接根 reactor 打包 |
| 测试编译失败 | 第一个失败模块与错误、现有测试是否匹配实现 | 保留失败事实，不以跳过测试宣布成功 |
| 端口被占用 | 用 `ss -ltnp` 定位监听者 | 只正常停止自己拥有的进程，不用 `kill -9` 随意清场 |
| JWT 配置启动失败 | Java 进程是否获得 `AUTH_JWT_SECRET` | 不输出密钥、不临时硬编码，不擅自轮换 |
| MySQL 拒绝连接/认证失败 | 实例、端口、用户名、Java 环境变量与本地数据库是否一致 | 不打印密码；已有卷的账户不一定跟新 `.env` 一致 |
| 业务表不存在 | Compose 未挂载 SQL；连接的库是否正确 | 按空库指南操作，已有库先核对结构 |
| 数据列与代码不匹配 | 实际 `SHOW CREATE TABLE` 与迁移 SQL | 重跑 IF NOT EXISTS 不能升级已有结构；需专门迁移方案 |
| Nacos 配置无效 | 地址、Namespace、Group、显式 Data ID `application.yml` | 不假定服务名 Data ID 会自动加载 |
| 网关路由 503 | 服务是否注册、发现地址、下游实例是否运行 | 不直接改成暴露内部服务给客户端 |
| 受保护请求 401 | Bearer 格式、过期、撤销、认证回源错误 | 401 也可能是认证依赖失败；不通过扩大白名单修复 |
| 有 Token 仍 404 | 路由和实际 Controller 是否存在 | 骨架服务不保证资料等接口已实现 |
| 注销后部分请求仍可用 | 调用是否经过网关、缓存删除是否失败、是否不同 jti | 按认证设计记录缓存窗口，不用 FLUSHALL 修复 |
| 角色/禁用状态未即时反映 | verify 使用 Token 声明、缓存命中，me 才读取实时账户 | 属于策略与实现差异，回流认证方案审查 |

## 结构与缓存诊断

数据库只查询必要结构与脱敏计数，禁止输出 `password_hash` 和真实账户资料。
Redis 在受控本地客户端使用 `SCAN` 和单键 TTL，禁止 `KEYS *`、全库清理或打印会话凭据。
缓存命名与所有权见 [数据库参考](../reference/database-schema.md)。

## 何时停止操作

目标环境未知、涉及共享数据、需要密钥轮换、切流或破坏性修改时停止，给出已查事实、影响与待确认事项。
如果只是文档与代码不一致，先记录差异，不把排障变成未经授权的代码修复。
