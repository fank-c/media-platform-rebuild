# 部署与回退边界

## 当前可用方式

当前仓库提供本地基础设施 Compose、Maven 构建和 Spring Boot JAR；Compose 不包含业务应用容器。
没有可据此执行的业务 Dockerfile、Kubernetes 清单、Helm 发布或 CI/CD 全流程。
原指南中将 Kubernetes 推荐为当前部署方式的内容不再作为操作说明保留；
它也不属于 [架构基线](../architecture.md) 的首阶段目标。

完整本地启动流程只维护在 [快速开始](../guides/quick-start.md)，建表与 Nacos 配置分别见
[数据库初始化](../database-setup-guide.md)、[Nacos 指南](../nacos-config-guide.md)。

## 本地部署核对

1. 确认是隔离本地环境，检查 `.env` 与 Java 进程变量分别生效，敏感值不提交。
2. 执行 `docker compose config -q`，确认守护进程可用后启动基础设施。
3. 确认业务表已手动初始化，不能因容器启动就认为建表完成。
4. 使用 `./build.sh -DskipTests` 打包，再按测试指南单独记录测试结果。
5. 先运行认证，再运行网关，验证注册发现、网关 ping 和完整认证流程。
6. 保存脱敏的构建版本、环境和验证结果；管理台仅本地受控访问。

## 共享或生产环境的准入条件（尚非部署脚本）

- 基础设施身份认证、网络隔离、最小权限、备份恢复和容量已验证；不能沿用本地开放端口与默认安全设置。
- 业务服务仅受信网关/内部调用可达，不能只依赖可伪造 Header。
- JWT 密钥管理、会话撤销窗口、禁用与角色变更语义经过审查。
- 数据迁移和版本兼容有脚本、核验与回退演练；旧客户端适配已完成。
- 健康检查、业务指标、日志脱敏和告警入口已落实；详见 [监控指南](monitoring.md)。
- 实际制品、配置版本和发布方法可复现；引入新基础设施或部署平台另行方案审查。

本次文档整合没有修改部署状态，也没有授权生产发布、双写或网关切流。

## 停止和回退

本地只停止当前任务启动的 Java 进程；基础设施可用 `docker compose stop` 停止并保留数据卷。
不要使用删除卷、删表或清空 Redis 作为常规环境清理步骤。

应用可回退到已验证制品与配置，但已经写入的数据和已发布消息需按专门方案处理。
流量切回单体、停止双写或重放消息必须在范围、验证和回退方案确认后执行。
目前网关配置没有可直接使用的旧单体切流开关，不提供假设存在的切换命令。

## Auth Outbox 快速投递的分阶段启用

此机制的默认配置是 `AUTH_OUTBOX_ENABLED=true`、`AUTH_OUTBOX_FAST_DISPATCH_ENABLED=false`、
`AUTH_OUTBOX_POLL_INTERVAL=1s`。先在隔离环境验证扫描基线和真实依赖，再将快速开关小范围设为 `true`；
通过拒绝量、积压年龄、数据库负载、重复量与注册延迟比较后，才可评估将扫描间隔调整为 10 秒。开关和线程池
只在启动期创建，修改需受控重启，不能假设 Nacos 热刷新会安全替换运行中资源。

回退优先关闭快速开关并恢复 1 秒扫描，不删除 Outbox、不重置 attempts、不自动重放 `FAILED`。总开关为
`false` 时只暂停发送而非停止注册写入，恢复前需核对积压容量和过期租约。生产、共享环境启用、消息重放和
流量切换均不在本次授权范围内。
